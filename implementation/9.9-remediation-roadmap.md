# 9.9 Remediation Roadmap

> Last updated: 2026-04-24
> Purpose: Convert the implementation audit into execution-ready constraints, milestones, and success criteria.

## Current Score

Current implementation score: 4.7 / 10.

Rationale:

- The Phase 1 static foundation is credible: Next.js, TypeScript, routes, typed domain models, static actor data, pillar pages, journey pages, ecosystem health, and governance pages exist.
- Build health is good: lint, typecheck, and production build passed when run through `cmd /c`.
- The MVP is not yet a true navigable ecosystem map. Phase 2 interaction work is 0 / 20 subphases, the map is a static list, search is absent, filters are absent, submissions are not functional, and no test suite exists.
- Data readiness is incomplete: the audit found 58 actor records, 0 actor coordinates, and no actor records counted in Starr or Willacy. Those underserved counties must be modeled intentionally rather than hidden.

## 9.9 Target State

The project reaches 9.9 / 10 when the V1 product can be trusted as public, open, useful shared infrastructure:

- Users can find relevant actors in under three minutes by role, intent, pillar, county, stage, status, and search query.
- The `/map` route has list, geographic, and pillar-oriented views using the same filtered dataset.
- The geographic map uses city-level coordinates, visible county context, clustering, accessible marker colors, and gap visibility.
- Gap records are first-class data, especially for Starr County and Willacy County.
- Community submission, correction, and gap flagging flows work end to end with review before publication.
- Actor, pillar, journey, gap, geography, filter, search, and component behavior are covered by CI-compatible tests.
- Ecosystem health is derived from data rather than hardcoded summaries wherever practical in V1.
- Governance, licensing, contribution, moderation, and data stewardship policies are explicit enough for open-source contributors.

## MVP Cut Line

The MVP must include:

1. Phase 2 in full: filters, search, map/list/pillar views, onboarding, responsive polish, and tests.
2. A minimal Phase 3: persistence and APIs only where needed for public data and submissions.
3. A minimal Phase 4: submission/correction/gap flag forms, moderation queue, audit trail, and community-added badges.
4. Public governance, data license, and contribution documentation.

The MVP must defer:

- CRM synchronization.
- Partner data feeds.
- Calendar/events.
- Advanced analytics beyond basic ecosystem health metrics.
- Public member accounts and claim/self-edit workflows unless needed for the moderation MVP.

## Launch Readiness Gates

The project cannot be called MVP-complete until all gates pass:

- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `npm test`
- Manual browser check for `/`, `/map`, `/search`, `/pillars`, `/pillars/[slug]`, `/actors/[slug]`, `/journeys`, `/journeys/[role]`, `/ecosystem-health`, `/submit`, and `/governance`.
- Mobile check at 320px, 390px, 768px, and desktop width with no horizontal scroll.
- Actor dataset has no duplicate ids or slugs.
- Actor dataset has 100% schema validation.
- Actor dataset has 100% city-level coordinates, or explicit documented exceptions.
- Starr and Willacy gaps are visible in product surfaces.
- Every public form has validation, confirmation, spam protection, and a moderation path.
- Every data mutation is auditable.

## Operating Rules For Execution Agents

- Work in the order of the MVP cut line unless the user explicitly reprioritizes.
- Do not start Phase 5 or Phase 6 until Phase 2, minimal Phase 3, minimal Phase 4, and test gates are complete.
- Keep PRD-backed requirements separate from optional future ideas.
- Any new feature must name the PRD section or implementation milestone it satisfies.
- Every completed subphase must update its progress tracker and record validation evidence.
- If a validation step cannot run, record the exact blocker in the relevant progress file.
